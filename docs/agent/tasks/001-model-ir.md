# Task 001 — Provider-neutral model IR

## Objective

Create the smallest stable contract through which the kernel can send a compiled
request to a frontier provider and receive a lossless stream of model events.
The IR must preserve advanced provider features instead of reducing them to text
chunks.

## Required boundary

Add a `model` crate only if it owns this reusable contract. It may depend on
`protocol` and capability schema types, but not on `apps` or a provider SDK.

The request must be able to carry:

- stable system prefix separated from volatile turn data;
- ordered conversation items and context capsule;
- a stable execution-epoch identifier;
- full paged tool schemas, not only capability cards;
- provider feature requests and opaque continuation state;
- cancellation/deadline metadata without credentials.

The output stream must distinguish at least:

```text
text delta
tool-call started
tool-call argument delta
tool-call ready
structured output
usage update
provider warning
completed with finish reason and optional continuation
failed
```

Tool calls require stable provider call IDs. A completed provider stream is not
a verified Ditto task completion.

## Non-goals

- no HTTP provider implementation;
- no process or SSH executor;
- no planner/executor workflow;
- no fake tool call generated by parsing assistant prose;
- no provider credential storage;
- no task-completed event.

## Design constraints

- Use a stream abstraction with backpressure and cancellation.
- Preserve unknown/provider-specific metadata in a bounded opaque field only
  where losing it prevents continuation; do not turn the whole API into `Value`.
- Feature flags report capabilities actually implemented by the driver.
- Prompt-cache-stable fields remain order-stable inside one execution epoch.
- Serialization is versionable and covered by round-trip tests.

## Acceptance tests

- text-only fixture emits ordered deltas and a completed finish reason;
- tool fixture emits started → argument deltas → ready with one stable call ID;
- malformed argument stream produces a typed failure, not a prose fallback;
- cancellation terminates the stream and does not emit task completion;
- usage and continuation survive serialization round trips;
- a driver cannot advertise a feature the development fixture does not emit;
- `./scripts/agent-check.sh` and MSRV CI pass.
