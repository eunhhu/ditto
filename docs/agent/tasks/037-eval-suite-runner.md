# Task 037: The Task 017 suite v1 and its runner

Contract and evidence in one file. The normative evaluation contract stays
[Task 017](017-evaluation-outcomes.md); this task only freezes suite v1 and
ships the tooling that produces and checks a report. On 2026-11-06 the user
asked to finish Ditto quickly so it can replace the current assistant
("빨리 완성시키고 헤르메스 대체하고싶네"); measured outcomes come first.

## Contract

- `eval/task017/suite-v1.json` freezes the ten minimum cases verbatim and adds
  T3, T4, S3, S4 and X2–X4 so every `(family, profile)` reaching a p95 budget
  has at least 20 attempts (Task 017 forbids budgets on fewer samples). The
  additions follow the same oracle rules and never weaken a minimum case:
  X2–X4 are mixed memory+sort cases and count toward semantic Recall@5 like
  X1; S3/S4 are once/repeat schedules with the same restart rules as S1/S2;
  T3/T4 are permitted and denied sorts. 130 planned attempts in total.
- `long_use` distractors are generated at indices 0..999 from the suite's
  template; the 256 inert capability headers are generated by
  `scripts/eval_task017.py fixture` and pinned by digest.
- `scripts/eval_task017.py run` drives the real daemon only over public
  routes, one fresh store per `(case, profile)`, seeded once and restarted
  before its attempts. Every attempt that does not finish is kept as
  `unavailable`, never dropped.
- `validate` parses the schema block of Task 017 itself, checks every digest
  against the content-addressed evidence directory, rejects unsafe or
  symlinked evidence paths, enforces one null reason per null observation,
  and recomputes all eight gates and readiness from raw evidence; a stored
  gate that disagrees with the recomputation is an invalid report.
- Answer grading is blind to profile and build: `run` exports a shuffled
  sheet with a fixed 20% second-review sample chosen before any grade
  exists; `grade --import` applies the lower score per axis on unresolved
  disagreement and stores each adjudication record as evidence.
- `freeze` derives ceilings (p95 × headroom, max × headroom) from a
  calibration run; a calibration report can never claim readiness.

## Measurement methods

- Latencies use the arrival time of each journal event on the live event
  stream (monotonic clock), not daemon timestamps.
- Inactive capability-body loads come from `strace -f -y` over the daemon:
  any `capability.toml` opened that the run did not select counts.
- Child peak RSS: the daemon reaps its sort child without rusage, and
  `ru_maxrss` inherits the forking process's high-water mark across exec, so
  each observed child is replayed with the identical argv, environment and
  stdin and its own `VmHWM` is read during an injected `exit_group` delay.
  The method is recorded with every value.
- Cost is priced at the metered list rate of the model actually used, even
  when calls ride a subscription, so efficiency compares across assistants.
  Usage carries no cached-token split, so all input is priced uncached.
- The runner builds the daemon it measures (`cargo build --locked --profile
  <build-profile> -p ditto-daemon`) and refuses to start when the binary's mtime
  is older than the newest Rust or capability source. Campaign 2 proved the need:
  a stale binary silently dropped `memory.manage` from capability selection, so
  every memory attempt answered "I don't have a memory search available in this
  session" and Recall@5 read 0.500 with no code defect behind it.
- A per-case rate threshold needs enough attempts to mean anything. The suite
  asks five repetitions per case, where a 3/5 and a 5/5 are two coin flips
  apart — observed directly on `X1`/`long_use`, which scored 3/5 in one run and
  5/5 in the next with the same binary. So a case-level gate applies its
  standard only at ten or more repetitions and otherwise blocks only below
  0.40, while the aggregate gate over the family and profile keeps 0.90
  (`case_threshold`).
- `scripts/eval_dry_model.py` is a scripted fixture model for checking the
  mechanics; a dry-run report is always `blocked` on integrity.
- OpenCode Go routes only requests that carry a per-conversation
  `x-opencode-session` and a client User-Agent, which Ditto's provider does
  not send. `scripts/eval_model_proxy.py` is a loopback forwarder that adds
  them (one session per attempt) without changing request or response
  content. Sending them from Ditto itself is follow-up work.

## Evidence

- Full dry run (release build, 2026-11-06, Raspberry Pi 5): 130/130 attempts
  observed, `validate` reports the report valid; integrity `blocked` (dry
  run), safety/tool/schedule `pass`, zero seed, idle and recovery model
  calls, zero inactive capability-body loads.
- The same dry run already shows a model-independent gap: memory context is
  compiled before any model call, and with 1,000 unrelated memories
  `long_use` Recall@5 is 0.50 (P1, P2, X1 miss; P3 finds one of two), so
  semantic is `fail` against the 0.90 floor. `clean` recall is 1.00.
- Live smoke on DeepSeek V4.1 Flash via OpenCode Go (T1 × 5, debug build):
  5/5 artifacts verified, about 4.8k input and 250–480 output tokens,
  about $0.0018 per attempt at the list price.
- Seeding 1,000 memories on the Pi's SD card showed 11–25 s stalls on single
  memory writes while other runs competed for I/O; seed calls now allow
  180 s.
- `scripts/test-eval-task017.py`: suite rejections, fixture digest
  reproduction, decimal pricing, and a real dry run whose report is forged,
  truncated, stripped of a null reason, tampered and symlinked — each
  rejected by `validate`.
- Calibration 1 (DeepSeek V4.1 Flash via OpenCode Go, release build, turn
  contract 14): $0.178 for 130 attempts at the list price; schedule 20/20 and
  sort artifacts 20/20 verified. 16 attempts (12%) failed because the
  provider ignored `parallel_tool_calls: false` and the kernel refused a
  second ready call - two memory searches, or an artifact read and its sort.
  `long_use` Recall@5 0.625: the model searched only with the request's words
  (P2), stopped after the first hop (P3), or did not search memory while
  sorting (X1). This led to turn contract 15 (ADR 0038) and its memory search
  instructions; the calibration is kept as the contract-14 baseline.
- The seed stalls are most likely SQLite WAL checkpoints (`synchronous=NORMAL`
  syncs only there) on the SD card, the Pi's only disk (unconfirmed); seeding
  is setup outside every measured attempt.
- Calibration 2 (contract 15, ready calls in order, memory guidance): one
  turn failure in 130 (none from batched calls); long_use Recall@5 0.775.
  Remaining misses: a lexical search for "flight" did not find "flights", and
  a turn stopped after the first hop. Two sort attempts sorted by hand after
  `artifact.read`, one asked for duplicate removal it was not granted.
- Calibration 3 (plural folding in memory search, ADR 0038): $0.233 for 130
  attempts at the list price; 128/130 verified; Recall@5 clean 45/45,
  long_use 43/45 (two P3 second hops); semantic, tool, schedule, safety and
  resource gates pass. Median completion: memory 2.8 s clean / 5.8 s
  long_use, schedule 1.8 s, sort 11.1 s, mixed 11.8 s / 18.3 s. Budgets in
  `eval/task017/budgets-v1.json` are frozen from this run; answer grading is
  still open.
